## 3. Product concept: LoanPilot AI

Product name: LoanPilot AI.

Product positioning:

An AI-powered lending distribution and relationship-manager productivity platform that ITC Infotech could potentially package and sell to multiple banks, NBFCs, lenders, and loan-distribution organizations.

This is a product concept, not an officially approved or existing ITC Infotech product. Do not imply that the company has committed to commercializing it.

### Core problem

Loan distributors and relationship managers spend substantial time on repetitive operational tasks:

- Responding to loan enquiries.
- Explaining product requirements.
- Registering and tracking leads.
- Following up with prospective borrowers.
- Collecting missing documents.
- Checking application status.
- Coordinating with internal operations teams.
- Updating CRM systems.
- Sending reminders.
- Preparing daily summaries and reports.

These activities are often fragmented across messaging apps, email, spreadsheets, CRM systems, and loan origination systems.

LoanPilot AI should help financial institutions manage the loan-distribution journey through conversational AI, controlled backend tools, workflow automation, and a relationship-manager dashboard.

Core capabilities:

1. Customer-facing conversational assistant.
2. Agentic AI orchestration with real backend tool execution.
3. Product knowledge retrieval using approved product information.
4. Lead creation, lookup, and duplicate detection.
5. Document checklist and document-status tracking.
6. Follow-up task creation and reminders.
7. Loan application status lookup.
8. Relationship-manager dashboard.
9. Human escalation and approval workflows.
10. Agent execution history and audit logs.
11. Daily email summaries using Amazon SES, if useful.
12. Configurable product and workflow policies.
13. An architecture that can eventually be adapted to different financial institutions.

The central workflow is:

Customer enquiry → AI understands intent → approved information retrieval → authorized tool execution → persistent record updates → customer response → RM dashboard update → follow-up or human escalation.

Build this as a reusable B2B product rather than a chatbot hardcoded for a single lender.

## 7. Agentic AI design

The application must demonstrate more than ordinary chatbot responses.

Build one primary orchestrator agent with a small set of well-defined tools. Add specialized agents only if they materially improve the workflow and can be completed reliably.

The agent should:

1. Understand the customer's intent.
2. Determine whether approved product information is needed.
3. Retrieve relevant facts from an approved source.
4. Select an appropriate authorized tool.
5. Execute the tool through the supported integration.
6. inspect the result.
7. Respond using the actual result.
8. Update workflow state only through authorized business operations.
9. Escalate uncertain or sensitive cases to a human.

Potential tools:

- `search_product_faq`
- `create_lead`
- `get_lead_status`
- `get_document_checklist`
- `record_document_receipt`
- `create_followup_task`
- `get_application_status`
- `escalate_to_human`

For every tool, define:
- Input schema.
- Output schema.
- Authorization rules.
- Validation.
- Expected side effects.
- Error behavior.
- Idempotency strategy.
- Audit events.
- Tests.

The LLM must not have unrestricted database access.

The Java backend must enforce business rules and authorization independently of the model's instructions.

Use an approved source for interest rates, fees, eligibility criteria, document requirements, and product terms.

If the source does not contain an answer, the agent must not invent one.

Never allow the agent to:
- Guarantee loan approval.
- Independently approve or reject credit.
- Invent rates, fees, or lender policies.
- Change loan terms without authorization.
- Treat document receipt as document verification.
- Bypass customer consent or access controls.

Maintain distinct document states such as:
`MISSING`, `RECEIVED`, `UNDER_REVIEW`, `VERIFIED`, and `REJECTED`.

Escalate sensitive financial decisions, suspicious documents, policy exceptions, and uncertain cases to authorized staff.
